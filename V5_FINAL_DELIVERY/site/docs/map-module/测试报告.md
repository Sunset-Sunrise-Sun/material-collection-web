## 4. 测试方法与工具链

### 4.1 为什么必须用 CDP 设备仿真

Windows headless Edge 存在**最小布局宽度约 504px** 的限制：用
`msedge --headless=new --window-size=390,844 --screenshot=...` 得到的“390px 截图”实际布局宽度仍是 504px，
页面按桌面断点渲染后被裁切，会**高估**移动端显示效果并掩盖横向溢出。因此本测试：

1. 以 `--remote-debugging-port` 启动真实 Edge 内核；
2. 通过 Node 24 内置 WebSocket 直连 CDP；
3. 用 `Emulation.setDeviceMetricsOverride {width:390,height:844,deviceScaleFactor:2,mobile:true}` 建立**真实布局视口**
   （实测 `innerWidth === 390`，`devicePixelRatio === 2`），并开启触摸仿真；
4. 用 `Page.captureScreenshot` 取图（物理像素 780×1688）。

### 4.2 交互全部走真实输入通道

| 交互 | CDP 命令 |
|---|---|
| 鼠标点击/悬停/拖拽平移 | `Input.dispatchMouseEvent`（mouseMoved / mousePressed / mouseReleased） |
| 滚轮缩放 | `Input.dispatchMouseEvent {type:'mouseWheel'}` |
| 移动端点按 | `Input.dispatchTouchEvent`（touchStart/touchEnd） |
| 键盘 Tab/方向键/Enter/Esc | `Input.dispatchKeyEvent`（keyDown/keyUp，带 windowsVirtualKeyCode） |
| 外部宿主脚本调用 API | `Runtime.evaluate`（模拟宿主调用 `select()` / `setMetric()` / `focusRule` 等） |

**关键教训**：仅用 `element.dispatchEvent(new MouseEvent('click'))` 直接派发到 `.district` 的“页面内自检”会绕过
真实指针事件路径，无法发现指针捕获导致 click 被重定向的问题（见第 7 节 DEF-01）。因此本测试器一律先
用 `ShadowRoot.elementFromPoint` 在区多边形内采样真实可命中坐标，再投递 CDP 输入事件。

### 4.3 断言与隔离

- 每个用例独立命名、记录耗时与失败原因；单个用例失败不中断后续用例；
- 页面内事件通过 `Page.addScriptToEvaluateOnNewDocument` 在文档创建前挂监听，捕获 `gzmap:ready/select/hover/metricchange/viewchange/reset` 的 `detail`；
- 控制台错误采集三路：`Runtime.consoleAPICalled(type=error)`、`Runtime.exceptionThrown`、`Log.entryAdded(level=error)`；
  favicon 404 单独记录为已知噪声（本模块页面用 `<link rel="icon" href="data:,">` 规避）；
- 网络采集 `Network.requestWillBeSent`，只允许 `http://127.0.0.1:<port>/` 本地资源与 `data:`/`blob:`；
- 截图 PNG 由测试器解析 IHDR 校验真实像素尺寸，防止“截图被缩放/裁切”假证据。

### 4.4 截图取景

桌面/移动截图均在目标视口下先 `scrollIntoView` 到地图卡片/组件顶部再截当前视口（不拼接整页），
因此图像尺寸严格等于视口（桌面 1440×900；移动物理 780×1688）。移动端“选中/缺失”状态由真实触摸点按产生，
缺失夹具由真实点按“加载缺失值测试夹具（合成）”按钮产生。桌面“选中”截图会先移出鼠标以隐藏 tooltip，
移动“选中”截图会先清除触摸点按产生的键盘焦点虚线，使“选中描边 + 详情面板”成为清晰证据。

**关于 demo `?selftest=1` 的说明（重要）**：本次独立复核该页面内自检在 headless CDP 环境下为 **130 / 131**，
唯一失败项是“键盘聚焦时绘制高对比焦点描边层”。经最小化复现确认：该自检通过 `element.focus()` /
`map.focusDistrict()` **程序化**移动焦点，而本 headless 配置下**程序化 focus 不派发 focus/focusin 事件**

不是组件缺陷：最终跑 E3 用真实 Tab 键验证焦点描边正常绘制（`.foc-outline` 路径长度 >100，描边为琥珀色
`rgb(180, 83, 9)`，与选中态深蓝可区分）。若要恢复页面内自检 131/131，建议该自检改用真实按键路径，
或在其自动化环境开启 `Emulation.setFocusEmulationEnabled {enabled:true}` 后复核。

## 7. 缺陷、偏差与回归记录

### DEF-01（已修复）真实鼠标单击地图区无法选中：指针捕获把 click 重定向到 `<svg>`

| 项 | 内容 |
|---|---|
| 严重度 | 高（桌面鼠标主路径不可用） |
| 发现时间 | 2026-10-28，预跑 C1/I1 用例（组件尚未冻结时） |
| 位置 | `src/gz-district-map.js`：`_onPointerDown` 中立即 `this._svg.setPointerCapture(e.pointerId)`；`_onClick` 用 `e.target.closest('.district')` 判定点击区（修复前 21:00 版约在 1761 / 1865–1871 行；修复后逻辑见同名方法） |
| 现象 | 对 `.district[data-adcode=440105]` 的真实鼠标点击：`selected` 保持 `null`，不派发 `gzmap:select`；若已有选中，点击区反而被当作“点击空白”清空 |
| 复现步骤 | 1440×900 → 打开 `http://127.0.0.1:8801/demo/` → 在区顶面路径上取真实命中坐标 → `Input.dispatchMouseEvent` 依次 mouseMoved / mousePressed / mouseReleased → 读取 `getState().selected` |
| 根因证据 | 实测事件序列：shadow `pointerdown` target=`path.top(440105)` → `pointerup` target=`svg.map` → `mouseup` target=`svg` → `click` target=`svg.map`。setPointerCapture 在按下时把后续指针事件重定向到 `<svg>`，而 click 是 PointerEvent，命中目标随之为 svg；`_onClick` 的 `e.target.closest('.district')` 为 `null` |
| 为什么此前未暴露 | demo `?selftest=1` 与早期探针直接 `district.dispatchEvent(new MouseEvent('click'))`，绕过了 pointerdown/pointerup 真实路径；触摸 tap 因触摸隐式捕获目标就是区，恰好正常 |
| 修复（map-dev，2026-10-28 21:05 版，组件冻结版） | ① 按下时不再立即 `setPointerCapture`，仅在位移超过阈值、确认进入拖拽后才捕获；② pointerdown 记录 `_downInfo={district,x,y,moved}`，`_onClick` 在 click 目标非区时回退为“按下命中的区 + 位移 <5px”判定；③ 拖拽/双指捏合结束设 `_suppressClickUntil = now+400ms`，抑制窗口内的 click 直接忽略，避免拖拽后误选/误清空 |
| 回归验证（最终跑） | 最终跑 48/48 通过，其中直接回归该缺陷的用例：C1（真实鼠标点击海珠）、C1b（真实鼠标依次点击越秀/番禺/花都 3 区）、I1（桌面选中截图依赖真实点击）、D5（以区为起点拖拽后不误选、抑制窗口后点击恢复）、E3（真实键盘焦点描边）。实现方自测 21/21、Lead 独立复跑 47/47 与本次 48/48 结论一致（本次新增 E3） |
| 教训 | “页面内自检”不能替代真实输入 E2E：合成事件会掩盖 pointer capture / 命中测试 / 触摸差异。建议保留 `?selftest=1` 作为快速自检，但验收必须以 CDP 真实输入为准（见 §4.5） |

### 9.1 未覆盖项（本次不宣称验证）

### 9.2 CDP 仿真与真机的已知差异

- 视口/DPR 由 `Emulation.setDeviceMetricsOverride` 精确设定，但无真机状态栏、安全区（`env(safe-area-inset-*)`）、虚拟键盘、浏览器 UI 工具栏占位；
- 触摸事件为合成 `Input.dispatchTouchEvent`，与真机驱动的时序/压力/多点轨迹存在差异；
- 无头模式字体渲染、GPU 栅格化与真机可能存在像素级差异（截图仅证明布局断言，不证明真机视觉完全一致）；
- `mobile:true` 仿真不改变 UA（本测试未做 UA 嗅探相关断言）；
- 本 headless 配置下**程序化 `element.focus()` 不派发 focus/focusin 事件**（普通 div/button 亦如此，真实按键才派发）。因此任何依赖“程序化 focus + 事件监听”的页面内自检（如 demo `?selftest=1` 的一项焦点描边用例）会呈现环境伪失败；本测试器用真实 `Input.dispatchKeyEvent` 的 Tab 路径验证焦点可见（E3），并在报告 §4.5 说明该差异。
